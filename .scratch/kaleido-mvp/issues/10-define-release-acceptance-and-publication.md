# Define release acceptance and publication

Type: grilling
Status: resolved
Blocked by: 01, 02, 04, 08, 09, 12, 13, 18

## Question

What integration matrix, artifact inspection, reproducibility proof, performance budget, provenance record, documentation, and publishing gates must pass before an Apache-2.0 Kaleido version is released publicly?

## Comments

- Research evidence: [`release-acceptance-publication-evidence.md`](../research/release-acceptance-publication-evidence.md) separates exact TestKit/AGP fixture mechanics, `bundletool` structure/APK/install/runtime proof levels, mapping and four independent reproducibility gates, Plugin Portal versus Maven Central requirements, Apache-2.0 obligations, and optional SBOM/SLSA provenance using current primary sources. It confirms that no external specification supplies Kaleido's performance or size thresholds.
- Decision round 1: public MVP release requires A3 (AGP `9.2.1`, Gradle `9.4.1`) and A4 (AGP `9.3.2`, Gradle `9.5.0`) with JDK 17, Build Tools `36.0.0`, compileSdk 36, AGP built-in Kotlin, Java-only Consumer coverage, and Compose Generator coverage. A1/A2 remain targets and enter the immutable Compatibility Matrix only after complete fixtures pass; their exclusion does not block the MVP, while A3 or A4 failure does. JDK 21, preview AGP, and extra Gradle pairs are non-blocking forward jobs and never expand support.
- Decision round 1: every public matrix row passes fixed-version `bundletool validate` and versioned device-spec `build-apks` across selected ABI/density/language/SDK boundaries. A3 and A4 each also install and start on at least one controlled device or Gradle Managed Device and run an automated Core Capability Set smoke covering generation, class/Manifest/XML rewrite, renamed resources, Full behavior, and Compose retention. These bounded checks do not claim all-device, all-path, or Play-review proof and belong to the plugin-version Kaleido Release Dossier rather than a Consumer Project Release Evidence Set.
- Decision round 1: the MVP has an authoritative public source repository and immutable release tag, publishes its binary through Gradle Plugin Portal only, and attaches source archive, Kaleido Release Dossier, checksums, and release notes to a GitHub Release. `validatePlugins`, `publishPlugins --validate-only`, and a post-publication clean Consumer fixture resolved from the public Portal are blocking gates. Maven Central is deferred until independent Maven coordinates justify its namespace, PGP, POM, sources/Javadoc, and dual-channel consistency cost.
- Decision round 2: every public Compatibility Matrix row consumes the real marker publication from an isolated temporary Maven repository and passes Java-only zero-DSL Safe, built-in-Kotlin zero-DSL Safe, and minified Full-plus-Compose complete Core Capability Set TestKit fixtures. A3/A4 additionally run the exhaustive flavored/multi-Consumer isolation, Protection/Escape Hatch, reflection/JNI, KAPT/KSP/Data Binding, Compose `512/513`, bad signing, unsupported topology, and fail-closed boundary suite. Sample App runs on every public row; Sana Reference Consumer runs production-scale clean Release, artifact inspection, and performance gates on A3/A4 with test signing and contributes no defaults.
- Decision round 2: Linux x86_64 is the authoritative full matrix, cache, byte-reproduction, and performance environment. macOS arm64 and Windows x86_64 each run A4 Safe and Full-plus-Compose end-to-end smoke covering separators, case behavior, file locking, and atomic movement; a failing platform is excluded from support. Cross-OS byte identity is not promised, and non-authoritative host results live only in the Kaleido Release Dossier.
- Decision round 2: on every public row, Configuration Cache runs the same Release invocation twice with second-run reuse and `problems=fail`; up-to-date proof disables Build Cache and requires eligible deterministic work to become `UP-TO-DATE` on the second run; Build Cache proof populates an empty cache, restores after clean in the same checkout, then restores from a different absolute checkout; clean-byte proof disables Build Cache and compares the complete Reproducibility Boundary across three independent clean workspaces with fixed locale, timezone, OS, JDK vendor, and toolchain. Non-cacheable signing/validation/publication still execute without changing deterministic evidence.
- Decision round 2: release artifact inspection requires clean resolution of marker/implementation publication and complete metadata/license/checksums; exactly one standard-path Regular/base-only final AAB with full signing, expected certificate, bundletool and conditional code-transparency validation; all raw/composed/resource mappings, real-stack retrace, Artifact Report schema and evidence-set digest closure; DEX/native/CT, resource-ID, Manifest/XML, Compose-retention, generation, and protection invariants; byte-identical Consumer `src/`; sentinel-secret/absolute-path absence across every output; and no partial or stale success after failure.
- Decision round 3: performance is measured on dedicated Linux A3/A4 runners against the identical Consumer without Kaleido after two warmups and five measured runs, using the median. Safe clean overhead is at most `max(20%, 45s)`, Full-plus-default-Compose clean overhead `max(30%, 90s)`, and warm no-change overhead `max(10%, 15s)`; peak RSS/heap increase is at most `max(25%, 512 MiB)`. Sample App and Sana both run, Sana is authoritative for relative budgets, and any observed quadratic transformation growth blocks release.
- Decision round 3: fixed device-spec `bundletool get-size total` limits Sana compressed-download growth to `max(1%, 1 MiB)` for Safe, `max(2%, 2 MiB)` for Full-plus-default-Compose, and `max(5%, 5 MiB)` for the Compose-512 stress fixture; Sample App absolute limits are 2 MiB and 4 MiB for Safe and Full-plus-Compose. The unshaded implementation JAR is at most 10 MiB, may not duplicate-shade Gradle/AGP/Kotlin, and newly resolved dependency payload is at most 50 MiB. Evidence growth must remain linear and its actual size is reported rather than given an app-independent cap.
- Decision round 3: Apache-2.0 publication requires root `LICENSE`, content-derived `NOTICE` and `THIRD_PARTY_NOTICES.md`, and a machine-readable provenance inventory of upstream URL/revision/files/original and modified digests/license/change notices. Reused AabResGuard material retains applicable notices and modification markings; AndroidJunkCode/XmlClassGuard source, template, generated-fragment, and distinctive-expression absence receives a similarity audit. All dependencies pass license and Gradle verification audit. Publication includes sources, a schema-valid CycloneDX 1.7 SBOM, a signed immutable Git tag, and a release manifest binding source, marker/implementation/metadata/archive/checksum/SBOM/Dossier digests; no unsupported SLSA level is claimed.
- Decision round 3: English is the canonical Portal documentation and Chinese may be a synchronized mirror. Required docs cover installation and Safe/Full/Compose/Protection/signing examples; Compatibility Matrix and hosts; DSL/defaults/diagnostics; Artifact Report/schema/mappings/retrace/evidence retention; threat model and bounded claims; measured performance/size; upgrades/deprecations; license/provenance; SECURITY, CONTRIBUTING, CHANGELOG, and release notes. The immutable Kaleido Release Dossier binds source revision, matrix, automated/device results, bundletool/device specs, four reproducibility gates, performance/size statistics, artifact/provenance/SBOM digests, docs version, human approval, and post-Portal smoke without secrets, user paths, or raw unsanitized logs.
- Decision round 4: one immutable Kaleido Release Candidate fixes source revision, version, dependency locks, toolchain, marker/implementation publication bytes, and every digest. All matrix, device, reproducibility, performance, licensing, and Portal gates test that same Candidate; release never rebuilds different bytes. The signed final tag points to the tested revision, and any source/dependency/schema/build/publication-byte change creates a new Candidate and restarts every hard gate.
- Decision round 4: A3/A4 Linux, controlled-device smoke, artifact closure, license/provenance, performance, reproducibility, documentation, and Portal validation have no waiver. A1/A2 or macOS/Windows may fail only when excluded from advertised support and recorded as such; preview/JDK21/forward jobs are non-blocking. A classified infrastructure failure may rerun the unchanged Candidate with the reason recorded, while a product assertion or budget failure requires a fix and new Candidate rather than rerun-to-green.
- Decision round 4: publication requires independent human approvals from a Release Owner for behavior/matrix/device/performance/Dossier completeness and a reviewer for licensing/provenance/secrets/version/docs/external content. Portal and release-signing credentials exist only in a protected release environment unavailable to untrusted PRs; Consumer fixtures use isolated non-production signing identities and never a Reference Consumer's real upload key.
- Decision round 4: after all internal gates, approvals, signed tag, final Dossier, draft GitHub Release, and final Portal validation, `publishPlugins` is the sole irreversible external publication. Kaleido then re-downloads public marker/implementation bytes, verifies their digests, and runs a clean Consumer Release smoke before finalizing GitHub Release assets. A public-resolution failure produces an immediate unsupported/do-not-use advisory and a new fully gated patch Candidate rather than overwrite or deletion; a GitHub outage only delays attaching the identical approved assets.
- Decision round 4: Play Console or a Play test track is not an MVP publication gate. Kaleido proves local AAB structure, APK-set generation, controlled installation, and bounded runtime smoke; Consumer Projects own Play accounts, tracks, credentials, policy acceptance, and store release. Optional Reference Consumer Play evidence may strengthen a Dossier later but cannot broaden the claim or require Kaleido to hold Consumer credentials.

## Answer

The public MVP accepts one immutable Kaleido Release Candidate only after every hard gate has evaluated the same source revision, version, dependency locks, toolchain, marker/implementation publication bytes, and digests. A3 (AGP `9.2.1`/Gradle `9.4.1`) and A4 (AGP `9.3.2`/Gradle `9.5.0`) on JDK 17, Build Tools `36.0.0`, compileSdk 36, Linux x86_64, AGP built-in Kotlin, Java-only Consumers, and Compose are mandatory. A1/A2, macOS, and Windows enter public support only after their declared complete fixtures pass; JDK 21, previews, and extra pairs remain forward-looking evidence.

Every public row consumes the real plugin marker from an isolated temporary Maven repository and runs Java Safe, built-in-Kotlin Safe, and minified Full-plus-Compose fixtures. A3/A4 add every capability boundary, unsupported-topology and failure fixture, Sample App, Sana production-scale build/performance evidence, fixed-version `bundletool validate`, device-spec APK generation, and controlled installation/startup/Core-Capability smoke. The Kaleido Release Dossier records this plugin-version proof separately from any Consumer Project Release Evidence Set and makes no all-device, Play-review, or store-acceptance claim.

Configuration Cache reuse, no-clean up-to-date behavior, same/relocated Build Cache restoration, and three independent clean byte reproductions are separate per-row gates. Artifact inspection closes the Portal publication, single final Regular/base-only AAB, signing/certificate/bundle/code-transparency validation, all mappings and real-stack retrace, Artifact Report and evidence-set identities, DEX/native/resource/XML/Manifest/Compose/protection invariants, untouched Consumer source, secret/path absence, and no partial or stale success.

On dedicated A3/A4 Linux runners after two warmups and five samples, median overhead versus the identical non-Kaleido Consumer is capped at `max(20%, 45s)` for Safe clean, `max(30%, 90s)` for Full-plus-default-Compose clean, `max(10%, 15s)` for warm no-change, and `max(25%, 512 MiB)` additional peak RSS/heap. Sana compressed-download growth is capped at `max(1%, 1 MiB)`, `max(2%, 2 MiB)`, and `max(5%, 5 MiB)` for Safe, Full-plus-default-Compose, and Compose-512; Sample caps are 2/4 MiB. The unshaded implementation JAR is at most 10 MiB, new dependency payload at most 50 MiB, and quadratic transformation growth always fails.

Apache-2.0 publication includes `LICENSE`, content-derived notices, machine-readable provenance, AabResGuard attribution/modification records, AndroidJunkCode/XmlClassGuard no-copy similarity audit, dependency license/verification audit, sources, CycloneDX 1.7 SBOM, signed immutable tag, release manifest, checksums, canonical English documentation, optional synchronized Chinese docs, and the complete sanitized Kaleido Release Dossier. No unsupported SLSA level is claimed.

The MVP publishes through Gradle Plugin Portal and an authoritative public source/GitHub Release, not Maven Central. `validatePlugins`, Portal dry-run validation, two independent human approvals, protected publication credentials, and post-publication public-resolution smoke are hard gates with no waiver. Infrastructure failures may rerun unchanged bytes with a recorded classification; product or budget failures require a new Candidate. A bad public version receives an unsupported advisory and a fully gated patch rather than overwrite or deletion. Play tracks and Consumer store credentials remain outside Kaleido publication. See [`ADR-0011`](../../../docs/adr/0011-publish-only-immutable-fully-evidenced-candidates.md) and the [`research evidence`](../research/release-acceptance-publication-evidence.md).
