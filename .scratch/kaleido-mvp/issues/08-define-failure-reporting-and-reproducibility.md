# Define failure, reporting, and reproducibility contracts

Type: grilling
Status: resolved
Blocked by: 05, 07, 17

## Question

Which findings fail the build, which safely degrade with warnings, what the Artifact Report and mappings contain, how seed and raw/composed mapping lifecycles work, and what reproducibility, cacheability, configuration invalidation, and incremental-build guarantees Kaleido makes for repeated builds with identical declared inputs?

## Comments

- Research evidence: [`failure-reporting-reproducibility-evidence.md`](../research/failure-reporting-reproducibility-evidence.md) separates Configuration Cache, up-to-date, Build Cache, relocatability, clean byte reproducibility, signing variability, remote-cache trust, sensitive Provider handling, and stable diagnostic facts using current Gradle/JDK/Android primary sources.
- Decision round 1: Kaleido diagnostics use stable `ERROR`, `WARNING`, and `INFO` levels and `KLD-<DOMAIN>-NNN` codes. Every diagnostic identifies the Consumer Project, exact variant, stage, declaration/input origin, affected target, reason, and actionable repair. The Adoption Contract exposes no error suppression or severity demotion.
- Decision round 1: an error means the Release cannot be published: invalid configuration/topology, unclosed references or Protection Requirements, inconsistent transform/mapping/receipt, protected-content changes, missing Release Evidence Set members, signature/certificate/Bundle/code-transparency failure, or an observed deterministic conflict. A warning is legal only for a pre-mutation, proven-safe retain/skip, a valid broad bounded Escape Hatch, dedup incompatibility, or an unconfirmed dynamic signal; cache disablement and ordinary cache misses are not Kaleido warnings.
- Decision round 1: each Release variant has one canonical UTF-8 versioned `artifact-report.json` as the machine source of truth; console output is a summary/path and the MVP produces no parallel HTML/Markdown report. `deterministicEvidence` records normalized effective inputs, seed/toolchain fingerprints, stage plan/receipt/output digests, generation/protection/mapping facts, and the unsigned candidate; `publicationEvidence` records the final signed AAB digest, upload-certificate identity, signature coverage, bundletool/code-transparency checks, and Release Evidence Set validation.
- Decision round 1: reports exclude raw seeds, signing secrets, passwords, host/user identity, absolute paths, wall-clock timestamps, durations, and cache hit/miss state. The deterministic section must not change merely because an eligible task executed locally, was up-to-date, or came from a cache.
- Decision round 1: the Reproducibility Boundary contains the generated tree, deterministic plans/receipts, R8 dictionaries/rules, raw/composed/resource mappings, transformed unsigned AAB, and `deterministicEvidence`. Identical normalized declared inputs, Consumer artifacts, seed fingerprint, and exact toolchain reproduce these bytes; exact final-signature bytes and `publicationEvidence` are excluded but must bind to the same unsigned digest, expected certificate, and valid complete signature.
- Decision round 1: the MVP promises task-level incremental correctness, not per-file incremental execution. Unchanged work may be up-to-date or cache-restored; a changed input invalidates only dependent stages of the affected variant, whose plan-first Module recomputes its complete immutable artifact. Variant/Profile/seed/toolchain/Protection inputs may never cross-reuse stale output, and no public `InputChanges` performance guarantee exists.
- Decision round 2: Configuration Cache reuse, no-clean up-to-date reuse, clean local/relocated Build Cache restoration, and independent clean byte reproduction are four separate gates. Configuration Cache runs twice with problems set to fail; cacheable work must restore after clean and from a second absolute checkout; true reproducibility disables Build Cache and compares the Reproducibility Boundary across independent directories and normalized locale/timezone conditions. No task outcome substitutes for byte comparison.
- Decision round 2: generation, analysis/protection/plan construction, dictionary/rule generation, Class/Manifest Rewrite, mapping generation/composition, and unsigned Bundle Rewrite may become cacheable only after repeated and relocated proof. Secret resolution/re-signing, final signature/certificate/Bundle/code-transparency/Release-Evidence validation, final Artifact Report assembly, and atomic publication are non-cacheable and execute. R8/AGP task caching remains AGP-owned.
- Decision round 2: plans, mappings, and deterministic report data are confidential build artifacts permitted in Consumer-configured local or remote Build Cache, whose operators and writers are part of the Consumer Project's trusted build infrastructure. Kaleido configures no cache endpoint and cannot mark one output local-only. Teams that do not trust a remote cache disable its use at the Gradle layer; secrets, private-key material, raw seeds, credential paths, and environment values never enter cacheable outputs.
- Decision round 2: an explicit root seed is normalized with Unicode NFC and UTF-8 and reduced to SHA-256; the default policy produces the same form. Only the digest feeds domain-separated derivation and declared task inputs. The Artifact Report records the full fingerprint and `seedPolicyVersion`, never the original string; a fingerprint change invalidates all affected generation, dictionary, mapping, and Bundle Rewrite work.
- Decision round 2: each variant publishes raw Kaleido class mapping, the original AGP/R8 mapping, a retrace-compatible original-to-final composed mapping, and resource mapping as current-build evidence outputs. Canonical UTF-8/LF files use stable ordering and schema/policy/toolchain identifiers, omit temporal/host/path data, and receive SHA-256 digests. The composed mapping is the normal retrace entry; raw files remain audit evidence; protected/unchanged targets and reasons live in the report rather than fabricated mapping rows. Mappings are never implicit inputs to a later build, and ticket 18 owns historical compatibility/retention policy.
- Decision round 3: Artifact Report v1 has canonical `schema`, `identity`, `deterministicEvidence`, `publicationEvidence`, `diagnostics`, and `proofLimitations` sections. Identity includes Kaleido/product/Consumer Project/variant/Profile and a `releaseEvidenceSetId`; deterministic evidence contains effective-plan, seed/toolchain, stage digest, generation/protection/degradation/mapping, and unsigned-content facts; publication evidence contains signed-AAB path/size/digest, certificate, signature algorithm/provider/JDK/TSA, JAR coverage, topology, bundletool, code-transparency, and atomic-publication results. Successful diagnostics contain stable sorted WARNING/INFO only.
- Decision round 3: `releaseEvidenceSetId` hashes a canonical identity manifest of the exact variant, unsigned and signed AAB digests, every mapping digest, deterministic-evidence digest, and upload-certificate identity. It is independent of clock time and output directory and closes every published member without self-referential report hashing.
- Decision round 3: only a completely signed, validated, atomically published result receives `artifact-report.json` and a new Release Evidence Set. Failed attempts may leave task-local debug material under `build/tmp` but never a partial report or publishable set; prior successful outputs do not represent the failed invocation, and CI must require the current Gradle invocation and current evidence-set identity to succeed. Every failure still emits a stable sanitized diagnostic, but early configuration failures need not create a file report.
- Decision round 3: invalidation follows semantic dependencies. Source/dependency changes invalidate compilation/analysis and downstream; Profile/generation changes invalidate affected generation/downstream; seed changes invalidate every derived-name generation/dictionary/mapping/Bundle stage; Protection changes invalidate analysis/plans and relevant downstream; Full resource-operation changes start at Bundle Rewrite; signing/certificate changes reuse the unsigned boundary and rerun signing/final validation/report/publication; tool/policy/schema changes invalidate every stage that consumes them. Variants remain isolated, and every dimension has positive and negative TestKit invalidation coverage.
- Decision round 3: Kaleido's diagnostic record is stable independently of Gradle's incubating Problems API, which may be an optional rendering adapter. Problems HTML, prose, stack traces, and log levels are not machine identity. Passwords, keys, environment values, raw seeds, credential URIs, command-line secrets, user-home paths, and keystore absolute paths are redacted at every log level without hashing; ordinary files use project-relative paths; signing records only source category and presence. Third-party exceptions are sanitized before any log, report, cache output, or exception chain.
- Decision round 3: contract tests cover stable diagnostic codes/fields/order/repairs; sentinel-secret/path absence across console/report/mappings/task outputs; report schema/canonical bytes/evidence-set member closure; retrace-compatible and byte-reproducible mappings; independent Configuration Cache/up-to-date/local and relocated Build Cache/clean-byte-reproduction gates; every declared-input invalidation edge; signing-only publication changes; no partial publication on failure; stale-output non-attribution; and equality of deterministic evidence after local execution versus cache restoration.

## Answer

Kaleido uses stable `ERROR`, `WARNING`, and `INFO` diagnostics identified by `KLD-<DOMAIN>-NNN`. Every diagnostic carries the Consumer Project, exact variant, pipeline stage, declaration or input origin, affected target, reason, and actionable repair. Errors cannot be suppressed or demoted. Only a pre-mutation, proven-safe retain/skip, a valid bounded Escape Hatch, deduplication incompatibility, or an unconfirmed dynamic signal may degrade to a warning; any condition that makes transformation integrity, evidence closure, signing, or publication unprovable fails the Release.

Each successful Release variant publishes one canonical UTF-8 `artifact-report.json` with versioned `schema`, `identity`, `deterministicEvidence`, `publicationEvidence`, `diagnostics`, and `proofLimitations` sections. Its `releaseEvidenceSetId` closes over the exact variant, unsigned and signed AAB digests, every mapping digest, deterministic-evidence digest, and upload-certificate identity without depending on time, host, output directory, or a self-referential report hash. Only a completely signed, validated, and atomically published result receives a new report and Release Evidence Set; failed attempts never publish partial evidence or attribute an older successful set to the current invocation.

The Reproducibility Boundary contains the generated tree, deterministic plans and receipts, R8 dictionaries and rules, raw Kaleido and AGP/R8 mappings, the retrace-compatible composed mapping, resource mapping, transformed unsigned AAB, and deterministic report evidence. Identical normalized declared inputs, Consumer artifacts, seed fingerprint, and exact toolchain must reproduce those bytes. Final signing bytes and publication observations are intentionally outside that boundary, but must bind to the same unsigned digest, expected upload certificate, and fully verified signature.

Configuration Cache reuse, no-clean `UP-TO-DATE` reuse, clean local and relocated Build Cache restoration, and independent clean byte reproduction with Build Cache disabled are four separate verification gates. Generation, planning, rewriting, mapping, and unsigned-Bundle work may become cacheable only after repeated and relocated proof. Secret resolution, re-signing, final validation, report assembly, and atomic publication execute and remain non-cacheable. Kaleido promises task-level incremental correctness with semantic, variant-isolated invalidation, not a public per-file `InputChanges` performance guarantee.

The normalized NFC/UTF-8 root seed is reduced to SHA-256 before derivation and task input use; reports expose only that fingerprint and the seed-policy version. Reports, mappings, diagnostics, task outputs, exceptions, and caches exclude secrets, raw seeds, credential values and paths, host/user identity, absolute user-home paths, timestamps, durations, and cache outcomes. Current-build mappings are canonical, digest-addressed evidence; ticket 18 owns historical mapping compatibility and retention. See [`ADR-0009`](../../../docs/adr/0009-separate-reproducible-unsigned-evidence-from-publication.md) and the [`research evidence`](../research/failure-reporting-reproducibility-evidence.md).
