# Define the class, XML, and resource transformation algorithms

Type: grilling
Status: resolved
Blocked by: 07, 16

## Question

Within the fixed Hardening Pipeline and keep/escape-hatch policy, which deterministic bytecode-renaming, Manifest/compiled-XML reference rewriting, ResourceTable/path transformation, duplicate-resource handling, collision detection, and validation algorithms satisfy the capability contracts across the supported AGP matrix, and what versioned intermediate schemas let each implementation remain a deep module behind its artifact interface?

## Answer

Kaleido implements class/XML/resource transformation as two deep, plan-first Modules: pre-R8 Class Rewrite and final-AAB Bundle Rewrite. Neither exposes ASM, Kotlin Metadata, AAPT2 protobuf, ZIP mechanics, arbitrary matchers, historical mappings, or mutation callbacks through the Adoption Contract.

Class Rewrite is reference-driven rather than a second whole-program obfuscator. Rename roots are eligible Application classes named by supported Manifest/layout/XML/Navigation/Data Binding locations plus Kaleido-generated classes. The target set adds only the Application-owned outer/inner, companion, file/multifile-facade, nest, and other identity closure required to keep those roots structurally valid. Dependency classes remain unchanged, protected identities remain fixed, and R8 owns ordinary remaining class/member obfuscation.

The class algorithm is a closed-world two-pass transform. Pass one inventories every class origin and version, standard JVM type-bearing surface, structural relationship, supported Kotlin Metadata model, semantic XML location, and Protection Requirement. It derives a complete mapping from a versioned domain-separated SHA-256 of the root seed, exact variant identity, target kind, and normalized original identity; legal short ASCII tokens extend deterministically on collision, preserve class-family `$` structure, never depend on encounter order, and consume no prior mapping. Before any mutation, Kaleido reserves every untouched/dependency identity and proves a normalized collision-free bijection.

Pass two applies one immutable mapping to all standard JVM class-file structures, output class paths, and structurally parsed Kotlin Metadata; ordinary strings are never globally replaced. Merged Manifest XML and final-AAB Manifest/layout/navigation/XML are parsed structurally and rewritten only at a versioned semantic registry:

- Manifest Application `name`, `backupAgent`, `appComponentFactory`, `manageSpaceActivity`, `zygotePreloadName`; Activity `name` and `parentActivityName`; Service/Receiver/Provider `name`; Activity Alias `targetActivity`; and Instrumentation `name`.
- Custom View element names, `<view class>`, Fragment `class`/`android:name`, `tools:context`, `layout_behavior`, and `layoutManager`.
- Nested Navigation destination `android:name` and custom `argType`.
- Data Binding variable/import types.

Locations are identified by namespace, element kind, and attribute resource ID and rendered with location-specific complete-name rules. `activity-alias@android:name`, generic metadata, resource strings, URLs, and unknown attributes are not guessed. An exact Application class name found outside the registry creates an original-name Protection Requirement before mapping; open-ended dynamic names remain Escape Hatch territory.

Bundle Rewrite preserves every resource package/type/entry ID, configuration, and value except explicitly authorized Full Profile string replacement or language filtering. For eligible resources it changes only `Entry.name`, the coordinated name-bearing `Reference.name`, every affected `FileReference.path`, and the corresponding base-module ZIP path. Resource and path tokens use the same versioned hash-derived allocation principle, are isolated by identity domain, preserve semantic suffixes such as `.9.png`, reserve untouched/dependency/protected identities, and undergo complete normalized collision checking before writing. DEX is never changed for resource renaming.

Duplicate-resource optimization is file-level deduplication, not resource-entry deletion or ID merging. Only compatible, unprotected, file-backed `res/` entries inside the base module qualify. Kaleido groups by SHA-256 and length, confirms byte equality, chooses a canonical original path by stable total order, redirects all matching `FileReference.path` values, and removes only redundant ZIP entries that have no remaining reference. It excludes other modules, assets, root files, native libraries, DEX, metadata, protected paths, unknown representations, and path-coupled resources.

Every mapping is planned atomically. Path and name normalization rejects absolute paths, traversal, backslashes, empty segments, invalid identifiers, case-fold conflicts, duplicate normalized inputs, and collisions with surviving outputs. Generated collisions extend their token deterministically; every unresolved collision and every many-to-one output other than a proven duplicate-file equivalence class fails before mutation.

Only three deterministic Protobuf artifacts cross the internal artifact seams:

- `ClassRewritePlan.v1`: input digests/origins, protections, structural closure, mapping, Manifest sites, and policy version.
- `BundleRewritePlan.v1`: AAB entry inventory, composed class mapping, protobuf XML edits, resource name/path/dedup actions, protections, and serialization policy.
- `TransformReceipt.v1`: actual input/output digests, applied/skipped counts, mapping closure, and validation results.

They carry schema ID/version, producer, exact variant, plan/input hashes, and sorted repeated fields rather than protobuf maps; unknown major versions fail. Executors accept only their exact plan and artifact inputs, validators compare original/plan/output/receipt, and human-facing raw/composed/resource mappings and the Artifact Report remain text or JSON. BuildService memory is never authoritative.

Unsigned Bundle serialization uses canonical UTF-8 entry order, fixed timestamps, explicit compression policy, deterministic protobuf serialization, and pinned bundletool/JDK inputs; it removes invalidated signature entries and non-semantic ZIP comments/extras while preserving DEX, native-library, and code-transparency paths and uncompressed bytes. Re-scanning proves unique paths, valid CRCs, file-reference closure, resource-ID identity, semantic XML closure, unknown-field preservation, and protected-content hashes.

A safe degradation is legal only before mutation and only when complete closure remains provable: a fully enumerable unsupported class family may retain its original identity; protected, dependency-owned, unknown-representation, or dedup-ineligible resources retain names/paths or skip deduplication. Unparseable/unbounded Metadata or opaque identity attributes, unresolved registered XML locations, ResourceTable/file-reference closure failures, digest mismatch, non-bijective mappings, illegal paths, unresolved collisions, unknown-field loss, protected-code change, or any unverifiable partial output fails the Release.

Class validation checks class-entry/`this_class` agreement, unique entries, absence of stale mapped identities in supported JVM/Metadata surfaces, target existence and reversibility, byte-identical untouched class content, ASM/JVM structure, strict Metadata reparsing, Merged Manifest closure, and exact plan/mapping/receipt hashes. Bundle validation checks unchanged resource IDs and authorized values, coordinated names/paths/XML, canonical dedup references, unchanged protected code, and exact plan/resource-mapping/receipt agreement. Every normal Release runs `bundletool validate`; `build-apks` and runtime fixtures remain release-acceptance/CI gates because bundletool cannot prove Kaleido mapping semantics.

Planning is bounded to hashing and sorting at no worse than `O(n log n)`; class/XML/resource scans and content digests are linear in total input bytes, byte comparison occurs only inside digest-collision groups, and ZIP payload work streams without retaining all resource bodies in memory. Contract fixtures cover the JVM/Kotlin identity matrix, every semantic XML site, multi-package/type/config ResourceTables, protected/dependency resources, file representations and collision cases, every safe-degradation/failure branch, mapping closure, protected-code identity, repeated-build determinism, and minified Release bundle validation.

See [`ADR-0008`](../../../docs/adr/0008-use-plan-first-identity-preserving-transforms.md).

- Decision round 1: Kaleido's pre-R8 class transform is reference-driven rather than a second whole-program obfuscator. Its rename roots are supported non-bytecode references and Kaleido-generated classes; it adds only the Application-owned outer/inner, companion, file-facade, nest, and other structural closure required for a consistent class identity. Dependencies remain unchanged and R8 owns ordinary remaining class/member obfuscation.
- Decision round 1: class transformation is a closed-world two-pass operation. The first pass inventories class identities, structural relationships, Protection Requirements, Kotlin Metadata, and target names and proves a collision-free bijection before mutation; the second remaps all supported JVM type-bearing structures, output paths, and Kotlin Metadata from that immutable mapping. Ordinary strings are never globally rewritten.
- Decision round 1: unsupported Metadata or an identity-bearing class attribute may degrade only by retaining the complete affected class-identity closure when that unchanged closure can be proven. If the surface or closure cannot be classified, the Release fails instead of emitting a partial transform.
- Decision round 1: merged Manifest XML and final-AAB protobuf Manifest/layout/navigation/XML are parsed structurally and rewritten only at versioned semantic class-identity locations. Unrelated text, URLs, resource strings, and unknown attributes remain unchanged; an in-scope location that cannot resolve through the class mapping fails.
- Decision round 1: resource transformation preserves every package/type/entry ID, configuration, and value, changing only eligible `Entry.name`, coordinated name-bearing `Reference.name`, `FileReference.path`, and the corresponding module ZIP path. DEX stays byte-identical, while dependency-owned and protected resource names/paths remain frozen.
- Decision round 1: duplicate merging is file-level deduplication, never resource-ID or entry deletion. Within the base module, compatible unprotected file-backed `res/` values must match by SHA-256, length, and byte comparison; a stable canonical path receives all matching `FileReference.path` values and only unreferenced duplicate ZIP entries are removed. Cross-module, assets, root, native, DEX, metadata, unknown-representation, and path-coupled inputs are excluded.
- Decision round 2: class, package, resource-name, directory, and file tokens derive from a versioned domain-separated SHA-256 of the root seed, exact variant identity, target kind, and normalized original identity. Legal short ASCII tokens extend deterministically on collision; class-family `$` structure and semantic file suffixes such as `.9.png` remain intact. Allocation never depends on encounter order and the MVP consumes no prior mapping; future reuse requires an explicit declared input.
- Decision round 2: every stage plans and validates its complete output namespace before mutation. It reserves untouched and dependency class names, protected and untouched resource identities, and all surviving ZIP paths; canonicalizes separators, case, path segments, and identifiers; rejects invalid or input-conflicting identities; and permits many-to-one output only for a proven duplicate-resource equivalence class. Generated-name collisions extend deterministically, while any unresolved collision fails.
- Decision round 2: the versioned semantic XML registry covers Manifest class-valued attributes on Application (`name`, `backupAgent`, `appComponentFactory`, `manageSpaceActivity`, `zygotePreloadName`), Activity (`name`, `parentActivityName`), Service/Receiver/Provider (`name`), Activity Alias (`targetActivity` only), and Instrumentation (`name`); custom View element names, `<view class>`, Fragment `class`/`android:name`, `tools:context`, `layout_behavior`, `layoutManager`; nested Navigation destination `android:name` and custom `argType`; and Data Binding variable/import types. Component alias `android:name`, generic metadata, strings, and unknown attributes are not guessed.
- Decision round 2: semantic locations are identified by namespace, element kind, and attribute resource ID rather than textual prefix matching. Each location resolves the original identity and uses a location-specific lexical renderer for the mapped complete class name; unresolved in-scope values fail and dynamic class-name couplings remain Protection Requirement/Escape Hatch concerns.
- Decision round 2: only `ClassRewritePlan.v1`, `BundleRewritePlan.v1`, and a common `TransformReceipt.v1` cross deep-module seams. The class plan contains input digests/origins/protections/structural closure/mapping/Manifest sites; the bundle plan contains entry inventory/composed mapping/protobuf XML/resource/path/dedup/protection/serialization actions; the receipt records actual digests, applied/skipped counts, closure, and validation. Deterministic Protobuf uses sorted repeated fields rather than maps and carries schema ID/version, producer, variant, and input hashes; unknown major versions fail, while human mappings and reports remain text/JSON.
- Decision round 2: unsigned Bundle serialization canonicalizes UTF-8 entry order, timestamps, compression policy, protobuf encoding, and the pinned bundletool/JDK toolchain; removes invalidated signature files plus non-semantic ZIP comments/extras; and preserves DEX, native-library, and code-transparency paths and uncompressed bytes. The writer then rescans path uniqueness, CRCs, file-reference closure, and protected-content hashes.
- Decision round 3: a transformation may safely degrade only before mutation and only when complete closure remains provable. A fully enumerable but unsupported class-identity closure is retained and reported; protected/dependency-owned/unknown-representation resources retain names or paths or skip deduplication; and an exact Application class name found outside the XML semantic registry creates an original-name Protection Requirement. Unparseable or unbounded Kotlin Metadata/opaque identity attributes, unresolved known XML locations, ResourceTable or file-reference closure failures, plan/input digest mismatches, non-bijective mappings, illegal paths, unresolved collisions, or any unverifiable partial write fail the Release.
- Decision round 3: Class Rewrite validation requires every class-entry path to equal `this_class`, unique entries, no stale mapped identity in any supported JVM/Metadata surface, existence and reversibility of every target, byte-identical content for untouched classes, ASM/JVM structural validation, strict Metadata reparsing, complete Merged Manifest semantic-site closure, and exact agreement among the output JAR, raw Kaleido mapping, plan digest, input digests, and `TransformReceipt`.
- Decision round 3: Bundle Rewrite validation proves an identical package/type/entry ID set; identical configurations and values except explicitly authorized Full string/language changes; closure across `Entry.name`, `Reference.name`, `FileReference.path`, ZIP paths, and every mapped protobuf XML site; unknown-field preservation; canonical-path existence and absence of references to removed duplicate paths; unchanged DEX/native/code-transparency paths and uncompressed bytes; and agreement among the plan, resource mapping, receipt, and artifact. Only digest-collision groups receive byte comparison. ZIP payload hashing and copying are streaming, so memory tracks metadata rather than all resource payload bytes; quadratic pairwise comparisons are outside the contract.
- Decision round 3: contract fixtures cover Java/Kotlin nested identities, companions, file/multifile facades, lambdas, invokedynamic/constant-dynamic, generics, annotations, records, sealed/nest/module attributes, and supported/unsupported Metadata; every Manifest semantic attribute including Activity Alias distinction; custom View/Fragment/Navigation/Data Binding and out-of-registry exact-name protection; multi-package/type/config ResourceTables and reference forms; protected/dependency resources; PNG, nine-patch, protobuf XML, digest/byte/representation/path edge cases; and minified Release mapping closure, protected-code identity, repeated-build determinism, and bundletool validation.
