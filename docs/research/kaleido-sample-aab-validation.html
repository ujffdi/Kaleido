资源与保护项明细

  • sample_status 在插件资源表中保持原名，符合资源名保护声明。
  • protected_probe_layout 的资源名和 base/res/layout/protected_probe_layout.xml 路径保持不变。
  • RuntimeProtectedEntry 在 baseline 被普通 R8 移除，在插件 AAB 中以原始类描述符存在。
  • locale_probe：baseline 具有 default、fr、zh-CN；插件包仅保留 default、zh-CN。
  • confirmed_unused_label：baseline 资源表存在；插件资源表不存在。
  • libobsolete.so 与 base/root/META-INF/DEPENDENCIES 仅存在于 baseline；libkeep.so 在两包中均保留。
  • 两组 duplicate drawable 的资源 ID 各自存在，但每组文件引用归并到同一规范化物理路径。

Compose 512 规模与缺陷修复

原配置 44 × 33 违反 Compose Generator 的公开边界：每文件最多 32 个函数、总数最多 512。 本次按确认方案改为 16 × 32 = 512。

第一次以 512 规模编译时暴露真实缺陷：全部函数被串成跨文件、深度 512 的调用链，Compose 编译器在 ComposerParamTransformer 中发生 StackOverflowError。修复将调用边限制在单文件内， 保持总量、确定性和闭环无环图不变，将最大路径深度降到 32。

新增契约回归测试先稳定失败、修复后通过；60,000 个普通方法加 512 个 Compose 函数的 release 构建随后成功。 修复没有提高 JVM 栈、降低生成总量或改变公开 DSL。
