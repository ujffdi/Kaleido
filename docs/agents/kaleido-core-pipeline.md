# Kaleido Core Pipeline

This is the source of truth for Kaleido Gradle-plugin scope, architecture, implementation, and integration testing. Product-scope questions are resolved against this contract; implementation research chooses how to satisfy it.

## Mandate

Kaleido is one Gradle plugin that combines four mandatory capability families in one automatic Release AAB pipeline:

1. **AndroidJunkCode-equivalent generation** — generate additional code, resources, and configured Manifest contributions during the build.
2. **XmlClassGuard-equivalent protection** — transform class names and keep Manifest/XML class references synchronized with the transformed bytecode.
3. **AABResGuard-equivalent processing** — obfuscate and optimize resources in the final AAB.
4. **Deterministic R8 handling** — generate a stable R8 dictionary and retain reproducible mapping artifacts for identical declared inputs, seed, and toolchain.

All four families belong to the Core Capability Set. Technical constraints change their implementation, task ordering, or compatibility policy; the finished plugin still delivers every family. The Consumer Project applies one plugin, configures one `kaleido {}` DSL, and runs its normal Release bundle command rather than orchestrating four independent plugins or manual guard tasks.

The Compose Generator is an explicitly enabled sub-capability of AndroidJunkCode-equivalent generation and ships in the first publicly releasable MVP; it is not a fifth capability family. It is disabled by default, supports only an already Compose-enabled Consumer Project, and shares Kaleido's generation, retention, reproducibility, and reporting infrastructure. Its detailed contract and acceptance evidence are release blockers for that MVP without making it mandatory for every Consumer Project.

## Adoption Contract

- Apply `com.tongsr.kaleido` after `com.android.application`. The only external seam is the optional managed `kaleido {}` DSL plus the normal `bundle<ReleaseVariant>` command; upstream engine types, AGP artifacts, task orchestration, executable callbacks, and capability enable switches are not public.
- Omitting the DSL selects Safe Profile and Safe Defaults v1: `<namespace>.kaleido.generated`, 4 packages, 4 ordinary classes per package, 4 methods per class, 8 layouts, 16 XML drawables, 32 strings, no Activities, Compose Generator disabled, and a `kld_<8-char-hash>_` resource prefix. Mandatory ordinary output counts remain nonzero.
- Derive the default root seed through a versioned stable policy from normalized application ID and exact variant identity. Accept one explicit root `Provider<String>` replacement and derive all variant/capability/name-domain sub-seeds internally; never use time, process randomness, locale, or host paths.
- `SAFE` is the default Profile. `FULL` only unlocks explicit Activity generation, typed native-library/metadata deletion, confirmed-unused-string replacement, and language filtering; it enables none of them by selection alone. Profile violations fail, and both Profiles always run all four capability families under the same protection policy.
- Expose product-intent declarations for generation, Full-only resource operations, typed Escape Hatches, and atomic upload signing. Keep class-reference algorithms, resource algorithms, R8 details, task order, report paths, and diagnostic suppression out of the Interface. Compose remains an explicit generation sub-capability whose block exposes only `enabled`, `fileCount`, and `functionsPerFile`.
- Apply top-level behavior to every eligible Release variant. Permit only complete upload-signing overrides by exact variant name; reject unknown/wildcard variants and per-variant Profile/capability overrides. Normalize all managed Provider-backed declarations into one versioned immutable Adoption Plan per variant.
- Resolve the complete atomic signing identity in this order: exact-variant DSL, top-level DSL, the complete `KALEIDO_UPLOAD_*` environment convention, then the complete `kaleido.uploadSigning.*` Gradle-property convention. A partial selected source fails without cross-source field merging, and secrets resolve only during non-cacheable signing execution.
- Emit stable, actionable diagnostics with code, project, variant, source/declaration path, and repair. Errors cannot be suppressed or demoted; use Gradle log levels for verbosity and always emit the Artifact Report for a successful Release Evidence Set.

## Compose Generator contract

- Leave Compose disabled in both Profiles until `generation.compose.enabled` is explicitly true. Then require `buildFeatures.compose == true`, the Compose compiler plugin on the Consumer Project, and Compose Runtime resolvable from every target Release compile classpath. Diagnose missing prerequisites without applying plugins, changing compiler configuration, or adding dependencies.
- Default to four files and four Composable functions per file. Accept `fileCount` in `1..64`, `functionsPerFile` in `1..32`, and at most `512` total functions. Inherit the generation package base and root seed; do not expose templates, imports, dependencies, graph depth, per-variant behavior, callbacks, UI, resource, component, or navigation controls.
- Register a variant-isolated generated Kotlin directory under `build/` through the public AGP variant source API. Use `<generation.packageBase>.compose` and derive deterministic file, JVM facade, function, graph, and content identities from the contract version, root seed, and exact variant identity without changing Consumer Project `src/`.
- Generate only internal top-level `@Composable` functions that import Compose Runtime and form a closed acyclic call graph. Permit pure computation, conditional branches, and generated-to-generated calls; prohibit UI/Foundation/Material/Activity/Navigation/tooling APIs, `@Preview`, resources, Manifest contributions, components/routes, startup entries, state/effect APIs, coroutines, I/O, logging, networking, reflection, Android platform calls, and Consumer Project symbols.
- Inventory the actual compiled JVM facades, logical functions, and `Composer`-lowered methods. Generate exact retention rules without `allowshrinking`, while permitting obfuscation and optimization; use composed mappings to prove every inventoried class and member remains in final Release DEX.
- Fail on invalid scale, any missing prerequisite, absent generation/lowering, incomplete mapping/retention, an ordinary incoming bytecode edge or exact generated-symbol reference, or any Manifest, Navigation, Preview, resource, component, or startup entry. Protection Requirements and Escape Hatches cannot weaken these invariants.
- Report Compose enablement, resolved scale and prerequisites, Runtime component/version, relative generated paths and hashes, compiled inventory/lowering, retention-rule provenance/hash, composed mappings, final DEX locations/counts, forbidden-entry scan results, and proof limitations without embedding complete generated source. Claim no Kaleido-declared static entry point, not absolute protection against arbitrary reflection, JNI, downloaded code/configuration, or third-party runtime behavior.

## Transformation algorithm contract

- Implement pre-R8 Class Rewrite and final-AAB Bundle Rewrite as deep, plan-first Modules. Before writing, inventory every input identity and Protection Requirement, derive the complete output mapping, reserve untouched/dependency/protected identities, normalize names and paths, prove a collision-free bijection, and bind the plan to exact artifact digests. Never make encounter-order or partial in-place mutation authoritative.
- Restrict Class Rewrite roots to Application classes referenced from supported non-bytecode semantic sites and Kaleido-generated classes, adding only required Application-owned outer/inner, companion, file/multifile-facade, nest, and equivalent identity closure. Keep dependencies and protected identities unchanged; let R8 obfuscate the remaining program.
- Derive class/package/resource/path tokens from a versioned domain-separated SHA-256 of the root seed, exact variant identity, target kind, and normalized original identity. Produce legal short ASCII identities, preserve class-family `$` structure and semantic file suffixes, and extend deterministically on collision. Consume no historical mapping in the MVP.
- Apply one immutable mapping to every supported standard JVM type-bearing structure, class output path, and structurally parsed Kotlin Metadata. Never perform arbitrary string replacement. Retain a fully enumerable unsupported identity closure only when unchanged closure is provable; fail on unparseable/unbounded Metadata, opaque identity attributes, or partial closure.
- Rewrite merged text Manifest and final-AAB protobuf Manifest/layout/navigation/XML only at a versioned semantic registry: documented Application/component/Instrumentation class attributes, custom View and Fragment sites, `tools:context`, behavior/layout-manager attributes, nested Navigation destinations/custom argument types, and Data Binding variable/import types. Treat Activity Alias `name` as component identity and only `targetActivity` as a class. Resolve by namespace/element/attribute identity, not textual prefixes; unknown exact Application class strings create original-name protection instead of guessed rewriting.
- Preserve every resource package/type/entry ID, configuration, and value except explicit Full string/language operations. Coordinate only eligible `Entry.name`, name-bearing `Reference.name`, `FileReference.path`, and base-module ZIP paths. Freeze dependency-owned and protected names/paths, reject invalid/colliding normalized outputs, and preserve DEX bytes.
- Deduplicate only compatible unprotected file-backed `res/` payloads inside the base module. Group by SHA-256 and length, confirm byte equality, choose a canonical path by stable order, redirect file references, and delete only redundant unreferenced ZIP entries. Never merge resource IDs/entries or cross module/assets/root/native/DEX/metadata/protected/unknown representation boundaries.
- Pass only deterministic `ClassRewritePlan.v1`, `BundleRewritePlan.v1`, and `TransformReceipt.v1` Protobuf artifacts across internal seams. Include schema/producer/variant/input hashes and sorted repeated fields, reject unknown major versions, and keep human raw/composed/resource mappings plus the Artifact Report separate. Executors consume exact plans; validators compare original, plan, output, mappings, and receipt.
- Canonicalize the unsigned Bundle with ordered UTF-8 paths, fixed timestamps, explicit compression policy, deterministic protobuf serialization, and pinned bundletool/JDK inputs. Remove invalid signature metadata and non-semantic ZIP comments/extras; preserve DEX/native/code-transparency paths and uncompressed bytes, then prove path, CRC, resource-ID, file-reference, XML, unknown-field, mapping, and protected-content closure before signing.
- Permit a safe degradation only before mutation and only with proven closure; otherwise fail. Class planning/validation is bounded by sorting/hash work at `O(n log n)` plus linear byte scans. Resource hashing/copying streams payloads, and byte comparisons occur only within digest-collision groups; quadratic pairwise comparison is outside the contract.

## Release pipeline

A configured Release AAB build has one ordered artifact chain:

1. Validate the Release variant, R8 requirement, declared configuration, and provider-backed signing prerequisites.
2. Generate AndroidJunkCode-equivalent sources, resources, and Manifest contributions, including Compose Generator sources when explicitly enabled, under `build/` and register them through AGP variant APIs.
3. Compile and merge the Consumer Project and generated inputs.
4. Analyze supported non-bytecode references, transform eligible Application-module classes before R8, and retain the raw Kaleido class mapping.
5. Synchronize `MERGED_MANIFEST`, generate deterministic class/package/member R8 dictionaries and coordinated rules, and preserve Kaleido-transformed target names through R8.
6. Run AGP/R8, retain its raw mapping, build the ordinary AAB, add optional code transparency, and apply AGP's initial upload signature.
7. Compose the raw Kaleido and R8 mappings into the original-to-final class mapping while retaining every raw mapping.
8. Apply deterministic final-Bundle compiled-XML/resource transformation, output the resource mapping and unsigned candidate AAB, and prove that DEX, native libraries, and any existing code-transparency JWT remain unchanged.
9. Re-sign through Kaleido-owned provider-backed inputs, verify complete JAR coverage and expected upload certificate, run structural and conditional code-transparency validation, and validate the Release Evidence Set.
10. Atomically publish exactly one final `SingleArtifact.BUNDLE` with its raw/composed mappings and Artifact Report; the AGP-signed input remains internal.

Stages hand off immutable, versioned file artifacts through declared Gradle inputs and outputs. Deterministic stages may claim Build Cache only after repeated-build proof; re-signing, final validation, and atomic publication are non-cacheable. The transformed unsigned content is the byte-reproducible boundary, while signing variability is reported separately.

## Failure, reporting, and reproducibility

- Emit stable `ERROR`, `WARNING`, and `INFO` records identified by `KLD-<DOMAIN>-NNN`. Include Consumer Project, exact variant, stage, declaration/input origin, affected target, reason, and actionable repair; sort successful WARNING/INFO records canonically. Never expose suppression or severity demotion. Fail invalid configuration or topology, unclosed references or protection, transform/mapping/receipt inconsistency, protected-content changes, incomplete evidence, signature/certificate/Bundle/code-transparency failure, and observed deterministic conflicts.
- Permit warning-only degradation solely before mutation when closure proves that retaining or skipping is safe, for a valid broad bounded Escape Hatch, for incompatible deduplication candidates that remain separate, or for an unconfirmed dynamic signal. Cache disablement and ordinary cache misses are neither Kaleido warnings nor reproducibility evidence.
- Publish exactly one canonical UTF-8/LF versioned `artifact-report.json` per successful Release variant. Artifact Report v1 has `schema`, `identity`, `deterministicEvidence`, `publicationEvidence`, `diagnostics`, and `proofLimitations`; console output is only a stable summary and report path, and the MVP produces no parallel HTML or Markdown report.
- Build `releaseEvidenceSetId` from a canonical manifest of the exact variant, transformed unsigned and final signed AAB digests, every raw/composed/resource mapping digest, deterministic-evidence digest, and upload-certificate identity. Exclude clock time and output directory and do not include the report's own digest. Create a new report and evidence set only after complete signing, validation, and atomic publication; task-local failure material may remain under `build/tmp`, but partial or stale evidence is never publishable.
- Define the Reproducibility Boundary as the generated tree, deterministic plans and receipts, R8 dictionaries/rules, raw and composed mappings, resource mapping, transformed unsigned AAB, and `deterministicEvidence`. Identical normalized declared inputs, Consumer artifacts, seed fingerprint, and exact toolchain reproduce these bytes. Final-signature bytes and `publicationEvidence` are outside the boundary but must bind to the same unsigned digest, expected certificate, and complete valid signature.
- Treat Configuration Cache reuse, no-clean up-to-date reuse, clean local and relocated Build Cache restoration, and independent clean byte reproduction with Build Cache disabled as four independent gates. Generation, analysis/planning, dictionary/rule construction, Class/Manifest Rewrite, mapping, and unsigned Bundle Rewrite may be cacheable only after repeated relocated proof. Secret resolution/re-signing, final validation, Artifact Report assembly, and atomic publication remain non-cacheable; AGP owns R8 caching.
- Normalize an explicit or default root seed as Unicode NFC encoded in UTF-8, reduce it to SHA-256, and use only the digest for domain-separated derivation and declared task inputs. Record the full fingerprint and `seedPolicyVersion`, never the raw seed. A changed fingerprint invalidates every affected generation, dictionary, mapping, and Bundle stage.
- Publish raw Kaleido class mapping, original AGP/R8 mapping, retrace-compatible original-to-final composed mapping, and resource mapping as canonical current-build evidence with stable ordering, schema/policy/toolchain identity, and SHA-256 digests. Use the composed mapping for normal retrace and the raw mappings for audit; do not fabricate rows for protected targets or consume a prior mapping implicitly.
- Redact passwords, keys, environment values, raw seeds, credential URIs, command-line secrets, user-home paths, and keystore absolute paths as `<redacted>` without hashing before any log, report, cache output, or exception chain. Use project-relative paths for ordinary files, record only signing-source category and presence, and exclude timestamps, durations, host/user identity, absolute paths, and cache outcomes from deterministic artifacts.
- Promise task-level incremental correctness rather than per-file execution. Semantic input changes invalidate only dependent stages for the affected variant: signing-only changes reuse the unsigned boundary, while source/dependency, Profile/generation, seed, Protection, Full resource-operation, tool, policy, and schema changes invalidate their declared downstream closure. Variants never cross-reuse outputs.

## Compatibility, versioning, and migration

- Publish one immutable Compatibility Matrix per Kaleido release. Each supported row names exact Kaleido, AGP patch, Gradle, runtime JDK, Build Tools, compileSdk, and Kotlin mode and passes a complete Release fixture. The MVP targets candidate AGP `9.0.1`–`9.3.2` rows but advertises only the proven subset; preview, untested, and generic “AGP 9” combinations are unsupported.
- Apply SemVer from `1.0.0` to the plugin ID, DSL types/properties/enums and Provider semantics, defaults and validation/failure behavior, Profiles, Compatibility Matrix, diagnostic machine identity, Artifact Report schema, Release Evidence Set membership/identity, and Kaleido-owned public mapping envelopes. Compatible fixes are patch; additive declarations/toolchain rows/schema fields/diagnostics and deprecations are minor; removal/rename, changed existing meaning or default, support shrinkage, diagnostic-identity change, and broken report/mapping reading are major.
- Keep internal engine types, task names/graph, Adoption Plan, stage plans, receipts, and cache formats outside the public Interface. Give every intermediate format explicit schema, policy, and producer versions as task inputs. An upgrade intentionally misses incompatible cache entries; never migrate task cache entries or mix producer/schema majors, and reject stale or unknown formats.
- Detect exact Gradle and AGP versions through public APIs and validate the complete Compatibility Matrix row before registering transform work, resolving secrets, or mutating artifacts. Fail unsupported, preview, or removed combinations through stable `KLD-COMPAT-*` diagnostics with detected versions, supported targets, and an upgrade/downgrade route; provide no force override. A still-supported row with scheduled removal may warn, while ordinary update availability never does.
- Deprecate a public DSL declaration, diagnostic field, or external schema member only in a minor while retaining its semantics. Keep it for at least one subsequent non-preview minor and 90 days, remove it only in a major, and publish a Bridge Release if needed. Emit one sanitized `KLD-DEPRECATION-*` warning with old declaration path, replacement, first deprecated version, and removal major; after removal, fail with an executable migration example rather than silently ignoring it.
- Give every Artifact Report an independent schema family, `major.minor`, immutable schema URI, and JSON Schema dialect. Schema minor evolution is backward-readable addition only; every Kaleido major reads all report minors it emits and the next Kaleido major reads at least the immediately previous report major. Do not promise forward-reading by old readers or indefinite latest-binary support.
- Keep every historical Release Evidence Set byte-immutable. A future converter may create only a derived view bound to source evidence-set identity, source member digests, target schema, and converter version. It never replaces, republishes, or changes the identity of the source evidence.
- Preserve per Release Evidence Set the exact raw Kaleido, original AGP/R8, retrace-compatible composed, and resource mappings plus R8/compiler and mapping versions, `pg_map_id`, `pg_map_hash`, full digests, composition version/input digests, and validated retrace-tool coordinates/version. Do not promise cross-release name stability or consume old mappings implicitly; retrace an artifact only with its matching published mapping.
- Partition upgrade diagnostics into `KLD-COMPAT-*`, `KLD-DEPRECATION-*`, `KLD-SCHEMA-*`, and `KLD-MIGRATION-*`. Every release publishes its Compatibility Matrix, SemVer classification, schema versions, deprecation/removal inventory, Bridge Release or multi-hop route, and executable migration examples.
- Migrate a breaking Consumer Project by validating and archiving its current Release Evidence Set, selecting an exact target row, entering the latest Bridge Release, clearing deprecations, then changing AGP, Gradle Wrapper, JDK/SDK, and target Kaleido major one dimension at a time. Treat the clean target build's old-cache misses as expected, validate the new evidence/retrace/Bundle/signing and four reproducibility gates independently, and retain the old set unchanged.
- Allow shortening the 90-day or Bridge Release minimum only for a confirmed security risk, legal/licensing requirement, or upstream removal that makes safe and correct support impossible. Still publish a new major and an advisory naming affected versions, rationale, and executable route; never hide the break in patch/minor, rewrite historical evidence, or represent it as new evidence.

## Supported topology

- A Consumer Project is one Project that applies `com.android.application` before Kaleido. Other Application Projects may coexist in the Gradle build and are isolated Consumer Projects if they also apply Kaleido; Kaleido does not inspect their mutable Project state.
- Process every enabled variant whose build type is exactly `release`, including product-flavor combinations. Isolate every variant's inputs, generated tree, mappings, final AAB, and Artifact Report. Fail when Kaleido has no eligible Release variant or a target Release variant has minification disabled.
- Allow ordinary local Android/JVM/Kotlin libraries, external AAR/JARs, project/module/file dependencies, annotation/KAPT/KSP-generated compiled inputs, and native libraries. Transform only Application-module and Kaleido-generated classes; analyze dependencies without rewriting their outputs.
- Reject Dynamic Features, Asset Packs, Instant Apps, non-Application plugin targets, applied hotfix/plugin frameworks, and confirmed direct Application-module external-code-loading/SplitInstall use; no generic force override admits them. Route dependency-only reflection/JNI/native/dynamic signals to the Protection Requirement/Escape Hatch policy and never claim that static scanning proves absence.
- Before Bundle Rewrite, require a `REGULAR` candidate AAB whose complete module map is exactly one `FEATURE_MODULE` named `base`; reject asset, extra feature, ML/AI, SDK-dependency, unknown, or any other module type.

## Protection and escape hatches

- Build one additive Protection Requirement set for every Release variant. Model reachability, original class/member identity, descriptor closure, runtime attributes, resource entry names, and packaged paths independently; a generic keep boolean or force bypass is not part of the contract.
- Coordinate-transform direct bytecode, class-literal, Manifest, XML, compiled resource-ID, binary-XML, and generated-code edges whose target sets are finite and closed. For exact string reflection and cross-validated JNI targets, preserve only the required original identities, reachability, descriptors, and attributes.
- Translate `tools:keep`, exact dynamic resource lookups, and public resources into existence and entry-name protection. Preserve packaged paths only for confirmed path coupling. Treat conflicting discard rules, zero-match declarations, and unclosed confirmed couplings as Release failures.
- Accept exact or bounded package/resource-prefix Escape Hatches only when they declare protection dimensions and a reason. Report resolved target counts and broad-pattern warnings; reject global bypasses. An Escape Hatch cannot admit unsupported external code loading, hotfix, or pluginization.
- Analyze final compiled KAPT/KSP/codegen outputs and retain dependency consumer rules with provenance. Dependency classes remain analysis-only and dependency-owned resource names/paths remain unchanged by default. Framework-specific automatic support requires a minified Release fixture.
- Apply the same policy in Safe Profile and Full Profile. Report discovered reflection/JNI/resource/runtime signals and the scanner's scope without claiming that absence of known signals proves absence of dynamic behavior.

## Implementation ownership

- **Public surface:** Kaleido owns the plugin ID, DSL, Profiles, task wiring, mappings, diagnostics, reports, and final artifact location. Upstream plugin types do not enter the public API.
- **AndroidJunkCode:** implement the capability inside Kaleido using upstream behavior and source as technical reference. AndroidJunkCode 2.0.0 is not the production dependency because the recorded Spike proves nondeterministic output, unavailable Build Cache reuse, and stale callback inputs. Retain its first-party Apache-2.0 publication metadata as research provenance, but do not copy upstream source expression, generator templates, or generated fragments without compatible permission. Owner clarification may strengthen provenance later but does not gate independent implementation or public publication; the Compose Generator remains Kaleido-owned and independently authored.
- **XmlClassGuard:** independently implement the required class, Manifest, and XML behavior. Treat the upstream project as behavioral reference unless compatible written permission is obtained.
- **AABResGuard:** Kaleido owns the AGP 9 integration and final-artifact lifecycle. Apache-2.0 algorithms may be reused selectively only with retained license, attribution, modification, and provenance records.
- **R8:** Kaleido owns dictionary generation, seed declaration, mapping retention, mapping composition, and reproducibility checks.
- **Signing:** obtain explicit signing inputs through provider-backed Consumer Project configuration rather than AGP internal credential providers, resolve secrets only during execution, keep them out of generated files, logs, mappings, and reports, and fail the Release build when transformation, re-signing, or verification fails.
- **Code transparency:** preserve and verify AGP-produced code-transparency metadata in the MVP. Final-Bundle rewriting may alter only non-code entries; any DEX, native-library, or CT-JWT path/content change fails closed rather than requiring Kaleido to own the CT private key.

Use supported AGP 9 variant and Artifact APIs. Generated content belongs under `build/`; Consumer Project files under `src/` remain unchanged. Every output-affecting option is a declared Gradle task input, deterministic tasks use stable seed and locale-independent behavior, and cacheability claims are backed by repeated-build tests.

## Public release contract

- Define one immutable Kaleido Release Candidate by source revision, version, dependency locks, toolchain, marker/implementation publication bytes, and digests. Every release gate consumes those same bytes; any source, dependency, schema, build, or publication-byte change creates a new Candidate and restarts all hard gates. The signed final tag points to the tested revision.
- Require A3 (AGP `9.2.1`, Gradle `9.4.1`) and A4 (AGP `9.3.2`, Gradle `9.5.0`) on Linux x86_64, JDK 17, Build Tools `36.0.0`, compileSdk 36, AGP built-in Kotlin, Java-only Consumer coverage, and Compose Generator coverage. A1/A2 may be omitted from the public Compatibility Matrix without blocking; macOS arm64 and Windows x86_64 are supported only after A4 Safe and Full-plus-Compose smoke; JDK 21, preview AGP, and extra Gradle pairs remain non-blocking forward jobs.
- On every public row, consume implementation and marker publications from an isolated temporary Maven repository and run Java-only zero-DSL Safe, built-in-Kotlin zero-DSL Safe, and minified Full-plus-Compose complete Core Capability Set fixtures. On A3/A4, also run flavored/multi-Consumer isolation, Protection/Escape Hatch, reflection/JNI, KAPT/KSP/Data Binding, Compose boundary, signing, unsupported-topology, and fail-closed suites, plus Sample App and Sana Reference Consumer gates with non-production signing.
- Validate every public-row AAB with a fixed bundletool, build APK sets for versioned device specs, and on A3/A4 install, start, and run controlled Core Capability Set smoke. Treat structure, APK generation, installation, and executed behavior as separate proof levels; never claim all-device, all-path, Play-review, or store-acceptance proof.
- Run the Configuration Cache invocation twice with reuse and `problems=fail`; run no-clean up-to-date proof twice with Build Cache disabled; populate an empty Build Cache and restore after clean in the same and relocated checkout; and compare the full Reproducibility Boundary across three independent clean, cache-disabled workspaces with fixed locale, timezone, OS, JDK vendor, and toolchain.
- Inspect clean Portal-style resolution and publication metadata; exactly one standard-path Regular/base-only final AAB; signature coverage, expected certificate, bundletool, and conditional code transparency; every raw/composed/resource mapping and real-stack retrace; Artifact Report/evidence-set digest closure; DEX/native/CT, resource-ID, Manifest/XML, generation, Compose, and Protection invariants; byte-identical Consumer `src/`; sentinel-secret/path absence; and failure without partial or stale success.
- Measure performance on dedicated A3/A4 Linux runners against the identical non-Kaleido Consumer after two warmups and five samples. Median overhead is at most `max(20%, 45s)` for Safe clean, `max(30%, 90s)` for Full-plus-default-Compose clean, `max(10%, 15s)` for warm no-change, and `max(25%, 512 MiB)` for extra peak RSS/heap. Sana is authoritative for relative budgets; observed quadratic growth always fails.
- With fixed device specs, cap Sana compressed-download growth at `max(1%, 1 MiB)` for Safe, `max(2%, 2 MiB)` for Full-plus-default-Compose, and `max(5%, 5 MiB)` for Compose-512; cap Sample App at 2/4 MiB for Safe/Full-plus-Compose. Keep the unshaded implementation JAR at or below 10 MiB, avoid duplicate-shading Gradle/AGP/Kotlin, keep newly resolved dependencies at or below 50 MiB, and report linearly growing evidence size.
- Publish Apache-2.0 with root `LICENSE`, content-derived NOTICE/third-party notices, machine-readable upstream revisions/files/digests/licenses/change records, retained AabResGuard notices and modification markings, AndroidJunkCode/XmlClassGuard no-copy similarity audit, dependency license and verification audit, sources, CycloneDX 1.7 SBOM, signed tag, and a release manifest binding all source/publication/archive/checksum/SBOM/Dossier digests. Claim no SLSA level that the build cannot verify.
- Maintain canonical English installation, Safe/Full/Compose/Protection/signing, Compatibility Matrix/host, DSL/default/diagnostic, report/schema/mapping/retrace, threat-model, performance, upgrade, license/provenance, security/contribution, changelog, and release documentation; a Chinese mirror may accompany it only while synchronized.
- Create an immutable Kaleido Release Dossier for the plugin version, separate from Consumer Release Evidence Sets, binding source revision, matrix, automated/device/bundletool results, four reproducibility gates, performance/size results, artifact/provenance/SBOM digests, documentation version, approvals, and post-Portal smoke without secrets, user paths, or raw unsanitized logs.
- Publish the MVP implementation through Gradle Plugin Portal and attach source archive, Dossier, checksums, SBOM, and notes to the authoritative GitHub Release. Require `validatePlugins`, `publishPlugins --validate-only`, a Release Owner approval, an independent provenance/security reviewer, protected credentials unavailable to untrusted PRs, and clean public-Portal resolution/smoke before finalizing the source release. Maven Central and Play tracks are not MVP gates.
- Permit no waiver for mandatory A3/A4 Linux, device, artifact, provenance, performance, reproducibility, documentation, or Portal gates. Rerun only a classified infrastructure failure against unchanged bytes; any product assertion or budget failure requires a new Candidate. Never overwrite a bad public version: publish an unsupported advisory and a newly gated patch.

## Work protocol

For a new architecture, implementation, or test task:

1. Read [`CONTEXT.md`](../../CONTEXT.md), the applicable [`docs/adr/`](../adr/), and the current source before proposing changes. Completion: the proposal uses repository vocabulary and names every affected core stage.
2. Trace the relevant upstream behavior and current AGP artifact path. Completion: every promised input, output, mapping, keep rule, failure mode, and signing consequence is accounted for with fact separated from inference.
3. Define the smallest vertical slice that advances one core stage without weakening the other three. Completion: its Gradle task inputs/outputs, artifact ownership, DSL surface, and automated acceptance checks are explicit.
4. Implement only when the active user request authorizes changes, then run the focused unit and Gradle TestKit/integration gates. Completion: test results distinguish automated proof from any remaining device or publication verification.
5. Update the capability contract, mappings/report schema, and decisions when behavior changes. Completion: one source of truth states each live rule and superseded conclusions cannot route later work.

Research may uncover blockers or force a different implementation strategy. Record those findings and choose a route that still delivers the Core Capability Set; reopening whether the four families belong in Kaleido requires an explicit product decision from the user.

## Acceptance contract

Kaleido is not complete until the integration fixtures prove all of the following:

- A Consumer Project applies only Kaleido and a normal `bundleRelease` automatically executes the configured pipeline.
- Plugin-only adoption resolves Safe Defaults v1 into an isolated Adoption Plan for every eligible Release variant; explicit Full, generation, Protection, signing, and exact-variant signing declarations obey their Profile, Provider, atomicity, and validation contracts.
- The target Project, every flavored Release variant, resolved dependency graph, and final Regular/base-only AAB satisfy the supported topology while unrelated Projects remain isolated.
- Generated code/resources and Manifest contributions participate in compilation, packaging, R8, and the final bundle while the Consumer Project's `src/` tree remains byte-identical.
- When Compose Generator is enabled in either Profile, Runtime-only generated functions compile with Compose lowering, reproduce at every scale boundary, have no forbidden static entry, and retain every inventoried mapped class/member in final Release DEX through R8 renaming and optimization; each missing prerequisite and a total-function request above `512` fails.
- Renamed classes resolve through bytecode, Manifest, XML, reflection/keep escape hatches, and supported generated-framework scenarios.
